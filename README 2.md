# Дашин день — офлайн-планер

Приложение для телефона и компьютера: расписание пар, задачи из календаря iCloud, привычки с галочками и статистика недели.
Открывается и работает **без интернета**. Галочки, поставленные офлайн, отправляются сами, когда появляется сеть, и видны на всех устройствах.

## Как это устроено

```
 Сайт колледжа ─┐                                   ┌─▶ iPhone / Mac «Календарь»
                ▼                                   │
        GitHub Actions (по расписанию) ──CalDAV──▶ iCloud (5 цветных календарей)
                │  ▲                                
                ▼  │ outbox (задачи из приложения)
           Supabase (база данных)  ◀──────▶  Приложение (GitHub Pages, офлайн-кэш на устройстве)
```

| Где | Что хранится / делает |
|---|---|
| **iCloud** | Главное хранилище событий: пары, задачи, дни рождения, врачи. Отсюда их видит «Календарь» на iPhone и Mac. |
| **Supabase** | Копия событий для приложения + привычки, галочки, очередь новых задач (`outbox`). Доступ только после входа. |
| **GitHub Actions** | Каждые 30 минут (6:00–23:30) переносит новые задачи в iCloud и обновляет копию событий. В 19:47 проверяет пары на сайте колледжа. |
| **GitHub Pages** | Само приложение. После первого открытия хранится на устройстве и работает офлайн. |

## Файлы

```
index.html, styles.css, app.js   — приложение
config.js                        — адрес и публичный ключ Supabase (заполнить)
sw.js, manifest.webmanifest      — офлайн-режим и установка на экран «Домой»
icons/                           — иконки
vendor/supabase.js               — библиотека Supabase (лежит локально, чтобы работало офлайн)
supabase/schema.sql              — таблицы и правила доступа
sync/                            — скрипты синхронизации (Python)
.github/workflows/sync.yml       — расписание синхронизации
```

## Настройка (один раз, ~20 минут)

### 1. Supabase — база данных

1. Зарегистрируйся на [supabase.com](https://supabase.com) → **New project**. Регион — `Central EU (Frankfurt)`, пароль базы сохрани куда-нибудь.
2. **SQL Editor → New query** → вставь всё содержимое `supabase/schema.sql` → **Run**.
3. **Authentication → Users → Add user → Create new user**: твоя почта и пароль (галочку *Auto Confirm User* включи). Этим логином будешь входить в приложение.
4. **Authentication → Sign In / Providers** → выключи **Allow new users to sign up**. Так никто, кроме тебя, не сможет завести аккаунт.
5. **Project Settings → API** (или **Data API / API Keys**). Понадобятся три значения:
   - `Project URL` — вида `https://abcd1234.supabase.co`
   - `anon` / `public` key — идёт в `config.js`, его можно светить
   - `service_role` / `secret` key — **секретный**, только в GitHub Secrets (шаг 2.4), никогда в код

### 2. GitHub

1. Открой `config.js` и впиши `SUPABASE_URL` и `SUPABASE_ANON_KEY`.
2. Создай репозиторий и загрузи **все** файлы проекта (включая скрытую папку `.github`).
   Публичный репозиторий — бесплатные Pages и безлимитные Actions. В коде нет личных данных: всё личное лежит в Supabase за логином.
3. **Settings → Pages** → Source: *Deploy from a branch* → `main` / `/ (root)` → Save. Через минуту появится адрес вида `https://<логин>.github.io/<репозиторий>/`.
4. **Settings → Secrets and variables → Actions → New repository secret** — добавь четыре секрета:

   | Имя | Значение |
   |---|---|
   | `APPLE_ID` | почта Apple ID |
   | `APPLE_PW` | пароль для приложений Apple (`xxxx-xxxx-xxxx-xxxx`) |
   | `SUPABASE_URL` | Project URL из шага 1.5 |
   | `SUPABASE_SERVICE_KEY` | `service_role` ключ из шага 1.5 |

5. **Actions** → включи workflows, если GitHub спросит → открой «Синхронизация календаря» → **Run workflow**. Через 1–2 минуты события появятся в базе.

### 3. Телефон

1. Открой адрес GitHub Pages в **Safari** на iPhone.
2. **Поделиться → На экран «Домой»**.
3. Открой иконку, войди логином из шага 1.3. Всё — дальше работает и без сети.

На компьютере просто открой тот же адрес в браузере (в Chrome можно «Установить приложение»).

## Как пользоваться

- **Галочки привычек и задач** — ставь в любой момент, даже без сети. Вверху справа видно состояние: `офлайн · 2 не отправлено` → `отправляю…` → `iCloud 19:57`.
- **Новая задача** — вкладка «Календарь» → «+ Добавить». В приложении появится сразу с меткой «ждёт iCloud», на iPhone — после ближайшей синхронизации (до 30 минут).
- **Удалить задачу** — нажми на неё → «Удалить из календаря».
- **Изменения в расписании пар** — показываются баннером на главном экране.
- **Обновить вручную** — нажми на индикатор вверху справа.

## Если что-то не так

- **Задачи не доходят до iPhone** — GitHub → Actions → последний запуск: красный значит ошибка, внутри будет текст. Частая причина — истёк или удалён пароль для приложений Apple.
- **Приложение не обновилось после изменений в коде** — в `sw.js` поменяй `VERSION` (например, `dd-v2`), закоммить, и открой приложение дважды.
- **Supabase поставил проект на паузу** — бывает, если неделю никто не заходил. Синхронизация каждые 30 минут этого не допускает; если всё же случилось — в панели Supabase нажми *Restore*.

## Безопасность

- `service_role` ключ и пароль Apple — только в GitHub Secrets. В коде их нет.
- `anon` ключ в `config.js` публичный по замыслу Supabase: без входа он не даёт доступа ни к одной строке (правила RLS в `schema.sql`).
- Регистрация новых пользователей выключена (шаг 1.4).
